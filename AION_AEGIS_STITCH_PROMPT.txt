DISEÑA LA INTERFAZ DE AION AEGIS — MOBILE-FIRST + DESKTOP RESPONSIVE

Usa el LOGO AION AEGIS que adjunté como referencia principal de identidad visual.

ESTA ES UNA TAREA EXCLUSIVAMENTE DE DISEÑO UI/UX.
No diseñes arquitectura técnica.
No expliques backend.
No representes agentes internos.
No dibujes diagramas de sistema.
No conviertas la propuesta en una presentación.
Diseña la INTERFAZ REAL de la aplicación y sus principales estados interactivos.

==================================================
1. IDEA DE EXPERIENCIA
==================================================

AION Aegis es una bitácora personal inteligente e interactiva.

La pantalla principal se llama AEGIS CORE.

Aegis Core debe sentirse como una mezcla muy refinada de:

- conversación moderna;
- bitácora viva;
- asistente personal;
- resumen del día;
- planificación;
- accesos a módulos profundos.

La experiencia debe ser:

ORGÁNICA
FLUIDA
RESPIRABLE
ELEGANTE
PREMIUM
MODERNA
MUY INTERACTIVA

No quiero saturación visual.
No quiero 12 tarjetas en pantalla.
No quiero un dashboard empresarial.
No quiero una pantalla clínica.
No quiero una hoja de cálculo convertida en aplicación.
No quiero una copia de ChatGPT con otro color.

La pantalla principal muestra POCO y deja profundizar cuando el usuario toca, expande o abre un módulo.

Frase de diseño:

“EL USUARIO VIVE Y CONVERSA; AEGIS ORGANIZA.”

- estética gamer;

- demasiados números simultáneos.

El logo puede conservar apariencia premium y luminosa.
La UI cotidiana debe ser más sobria y limpia.

==================================================
4. BARRA SUPERIOR DESKTOP
==================================================

Debe ser minimalista.

Izquierda/centro:
- contexto actual, por ejemplo “Aegis Core” o nombre del módulo.

Derecha:
- notificaciones;
- búsqueda opcional;
- configuración rápida;
- avatar/perfil.

No llenar la barra con controles.

==================================================
5. AEGIS CORE — ESTRUCTURA GENERAL
==================================================

Aegis Core NO debe ser una cuadrícula fija.

Debe ser un FEED VERTICAL ORGÁNICO.

Orden sugerido:

1. header contextual muy corto;
2. área conversacional / composer;
3. acciones rápidas contextuales;
4. Pulso de hoy;
5. Aegis detecta;
6. Plan Vivo breve;
7. Mi Día breve;
8. Mis módulos;
9. Ayer / tendencia reciente solo si aporta valor;
10. reportes/exportación como acción secundaria.

Una sección sin información útil puede ocultarse o quedar colapsada.

==================================================
6. MOBILE — PRIMER VIEWPORT
==================================================

Diseñar primero una pantalla móvil aproximadamente 390 x 844.

El primer viewport debe sentirse MUY LIMPIO.

Header:

☰  + logo/nombre AION Aegis + 🔔 + avatar

Debajo:

saludo contextual muy corto

“¿Qué está pasando?”

Después un COMPOSER GRANDE Y ELEGANTE.

Placeholder:

“Cuéntame, muéstrame o pregúntame algo…”

Dentro del composer:

- micrófono;
- cámara;
- adjuntar;
- enviar.

Debajo máximo 2 o 3 acciones rápidas.

Ejemplo visual:

[ Ya comí ]   [ Tomé agua ]   [ ¿Qué puedo comer? ]

Después, como máximo UNA señal relevante.

Ejemplo:

Aegis nota
Dormiste menos que tu patrón habitual.  >

NO mostrar ocho métricas en el primer viewport.

==================================================
7. MOBILE — SCROLL VERTICAL
==================================================

El usuario debe poder deslizar naturalmente hacia abajo.

No comprimir toda la app en una sola pantalla.

Después del primer viewport aparecen, si aportan valor:

AHORA / PULSO DE HOY
AEGIS DETECTA
PLAN VIVO
MI DÍA
MIS MÓDULOS
AYER
REPORTES

Cada bloque debe tener suficiente espacio negativo.

==================================================
8. BOTTOM NAVIGATION MOBILE
==================================================

Usar SOLO cuatro destinos:

AEGIS CORE
MI DÍA
+ REGISTRAR
MÁS

MÁS abre un navigation drawer con todos los módulos y configuración.

10. COMPOSER STICKY
==================================================

“Preguntar a Aegis…”      🎙   📷

==================================================
11. PULSO DE HOY
==================================================

NO hacer varias cards.

Crear una sola superficie compacta con 2 a 4 elementos pertinentes.

Ejemplo:

AHORA

Sueño 6 h 42 min · Despierto hace 18 min
Última ingesta hace 10 h 20 min · Próximo: caminar 09:30

O:

Almuerzo hace 2 h 10 min · Agua 1.4 L
Energía 7/10 · Próximo: entrenamiento 18:30

Cada elemento debe poder tocarse para ampliar.

Los datos no exactos pueden llevar un badge muy discreto:

medido
confirmado
calculado
estimado
probable

==================================================
12. AEGIS DETECTA
==================================================

Mostrar máximo 1 o 2 señales prominentes.

Ejemplo:

Aegis detecta

[ Ver recetas ]   [ Ignorar ]   [ ⋯ ]

Otro ejemplo:

No encuentro almuerzo registrado.

[ Ya comí ]   [ Todavía no ]   [ Omitir ]

El menú ⋯ puede ofrecer:

- recordar luego;
- no volver a mostrar esto;
- ver por qué apareció.

==================================================
15. MIS MÓDULOS — INSPIRADO EN MÓDULOS SATÉLITE
==================================================

Quiero recuperar la idea de módulos satélite configurables, pero con diseño moderno y limpio.

NO usar grid 3x4.

Usar preferiblemente lista/accordion compacto:

MIS MÓDULOS

Alimentación            Hoy en curso          >
Sueño                   Último registro       >
Actividad               32 min hoy            >
Despensa                2 por revisar         >
Plan Vivo               3 pendientes          >

[ Ver todos ]

Cada módulo puede:

- abrirse;
- expandir un resumen corto;
- colapsarse;
- fijarse en Aegis Core;
- quitarse de Aegis Core;
- reorganizarse.

Usar menú ⋯ en cada módulo:

Fijar en Core
Desfijar
Ocultar de Core
Mover arriba
Mover abajo
Abrir módulo

IMPORTANTE:
Ocultar de Core NO significa eliminar el módulo.

18. RESPUESTAS VISUALES
==================================================

La conversación NO debe devolver solo párrafos.

Diseñar respuestas que puedan mezclar:

- texto breve;
- tarjeta;
- imagen;
- receta;
- mini gráfica;
- timeline;
- rango;
- botones;
- chips;
- progresos;
- resumen de acción;
- enlace “Ver en módulo”.

Ejemplo de respuesta a:

“Tengo hambre.”

Aegis responde brevemente y muestra dos opciones, no cinco.

OPCIÓN 1
Huevos + tomate
~310 kcal · 26 g proteína · 12 min
Usa tomates que conviene consumir pronto.
[ Ver receta ] [ Elegir ]

OPCIÓN 2
Atún + ensalada
~260 kcal · 32 g proteína · 8 min
[ Ver receta ] [ Elegir ]

Debajo:
¿Por qué estas opciones?

==================================================
19. FLUJO VISUAL DE FOTO DE COMIDA
==================================================

Diseñar este flujo como pantallas/estados visuales:

1. cámara / seleccionar foto;
2. preview;
3. estado “Analizando…”;
4. lista breve de alimentos detectados;
5. una pregunta visual si algo es ambiguo;
6. estimación de porciones;
7. confirmar/corregir;
8. resultado;
9. resumen de lo registrado.

Ejemplo:

Veo probablemente:

✓ arroz                         alta
✓ pollo a la plancha            alta
✓ tomate/cebolla                media-alta
? lo blanco podría ser queso o salsa

¿Es queso o salsa?

[ Queso ] [ Salsa ] [ Otra cosa ]

Después:

ESTIMACIÓN

Arroz       140–180 g
Pollo       160–210 g
Ensalada     70–100 g

[ Confirmar ] [ Ajustar ]

20. CORREGIR FOTO / INGREDIENTE

23. “¿POR QUÉ?” / DETALLE DE EVIDENCIA
==================================================

Cuando el usuario toca “¿Por qué?” abrir:

- drawer lateral en desktop.

Estado: PROBABLE

• última comida 08:12
• caminata 32 min
• hora actual 12:38

Botones:
[ Ver detalle ] [ Cerrar ]

==================================================
35. INTERACCIONES GENERALES
==================================================

Tap = abrir/expandir.
Long press o ⋯ = acciones secundarias.
Swipe = solo cuando sea obvio.
Drag = ordenar módulos o Plan Vivo.
Pull to refresh = sincronizar/actualizar.

Usar:

- bottom sheets;
- drawers;
- accordions;
- expand/collapse;
- sticky composer;
- chips;
- cards accionables;
- tooltips desktop;
- haptic feedback sugerido en móvil.

No esconder funciones críticas únicamente detrás de gestos.

==================================================
36. MOTION
==================================================

Animaciones suaves de 150–250 ms.

- expandir/colapsar;
- abrir drawer;
- bottom sheet;
- feedback de registro;
- foco del composer;
- pequeño pulso violeta mientras procesa.

El logo puede tener una respiración casi imperceptible.

No usar partículas permanentes.

==================================================
37. RESPONSIVE
==================================================

MOBILE:
- una columna;
- scroll vertical;
- bottom nav;
- drawer;
- bottom sheets;
- sticky composer;
- módulos a pantalla completa.

TABLET:
- sidebar compacta o drawer persistente;
- una o dos columnas;
- más espacio, misma jerarquía.

DESKTOP:
- sidebar colapsable;
- gran área central;
- panel de detalle lateral solo bajo demanda;
- no llenar el ancho extra de información innecesaria.

==================================================
39. CRITERIO DE RECHAZO
==================================================

No aceptar una propuesta si:

- parece un dashboard corporativo;
- muestra todos los módulos simultáneamente;
- llena Core de números;
- solo diseña una caja de chat;
- no tiene scroll orgánico;
- no tiene navegación completa;
- no tiene módulos expandibles;
- no permite fijar/ocultar/reordenar resúmenes de módulos;
- no tiene cámara;
- no tiene voz;
- no tiene corrección;
- no tiene estados de éxito/error;
- omite Configuración;
- móvil parece desktop comprimido;
- el dorado/violeta saturan;
- parece gamer;
- obliga a mirar todo a la vez.

RESULTADO FINAL:

AION Aegis debe sentirse como una inteligencia personal premium, tranquila y viva.

La pantalla principal debe respirar.

La profundidad debe existir, pero aparecer solamente cuando el usuario la abre.
